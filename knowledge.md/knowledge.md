# АРХИТЕКТУРНЫЕ ПРИНЦИПЫ (НЕ НАРУШАТЬ)


## Compliance-by-Design

- У контакта отдельные поля для каждого канала: ID канала, consentAt, consentSource, consentVersion, unsubscribedAt.
- Отправка возможна ТОЛЬКО если одновременно: (a) есть ID канала, (b) unsubscribedAt IS NULL, (c) consentAt IS NOT NULL, (d) канал не помечен как недоступный (blockedAt IS NULL).
- Эта проверка выполняется в воркере непосредственно перед отправкой, а не только при постановке в очередь.
- Команда /start сама по себе НЕ считается согласием на рекламу. Бот после /start присылает текст согласия (версия хранится в consentVersion) и inline-кнопку «Согласен получать рассылки». Согласие фиксируется только по нажатию кнопки (callback_query).
- /stop и кнопка «Отписаться» мгновенно выставляют unsubscribedAt.
- Событие my_chat_member со статусом kicked (пользователь заблокировал бота) выставляет blockedAt.
- Сервисные (неrекламные) сообщения отделяются от рекламных полем kind (SERVICE | MARKETING). Рекламные требуют согласия по всем условиям выше.

## Адаптерный паттерн

- Единый интерфейс IChannelAdapter: sendMessage(), parseWebhook(), verifyWebhook().
- Ядро не знает о специфике Telegram/MAX.
- Каждый канал — отдельный NestJS-модуль.

## Идемпотентность (атомарная)

- Каждое входящее событие имеет eventId (Telegram: tg_<update_id>).
- Запись в ProcessedEvent и бизнес-обработка выполняются в одной транзакции Prisma.
- Не использовать «findUnique → create». Делать create и ловить P2002 (unique violation) как признак дубля.
- Если транзакция откатилась, событие не считается обработанным, Telegram сможет повторить его.

## Очередь отправки

- Все исходящие идут через BullMQ.
- Глобальный лимит для Telegram ≈ 30 сообщений/сек, на один чат ≈ 1 сообщение/сек. Лимиты настраиваются через конфиг.
- Retry с exponential backoff. При ответе 429 использовать parameters.retry_after из ответа Telegram.
- Ошибка 403 (bot blocked) — не ретраить, выставить blockedAt.
- В job передаётся messageId (UUID записи Message в БД), а не Telegram chat id.

## Безопасность

- Проверка X-Telegram-Bot-Api-Secret-Token обязательна. Если секрет не задан в .env, приложение не стартует.
- Токены и секреты не логировать. В логах не хранить полные payload с персональными данными (маскировать или логировать только тип события и id).

## BigInt

- Telegram chat id хранится как String в БД (без проблем с JSON-сериализацией BigInt).
